# TrendCast｜走勢推演

> 專案構想草稿；名稱暫定為 TrendCast。

## 想做什麼

開發一個股票走勢分析程式，透過免費 API 自動取得至少最近兩年的每分鐘行情，整理後交給 Jev 分析，嘗試推測未來走勢，並用實際行情驗證預測效果。

希望最終能呈現歷史價格與未來走勢推演，讓使用者看見預測結果、實際結果，以及兩者的差距。

## 資料需求

- 透過 API 自動取得資料，僅使用免費的股市資料來源，資料取得費用為零。
- 至少涵蓋最近兩年的交易時段，並持續補入新資料。
- 暫以「1 分 K」理解每分鐘行情：時間、股票代號、開盤價、最高價、最低價、收盤價及成交量。
- 檢查資料缺漏、重複、成交量單位，以及除權息、股票分割造成的價格變化。
- 如果要在盤中持續預測，需要能取得最新行情；歷史資料的盤後更新服務需另外評估是否足夠。

目前先以台股作為討論前提，實際市場與第一檔股票待確認。API 供應商尚未決定，需評估免費方案的歷史長度、完整性、更新速度及呼叫限制；是否能同時滿足「至少兩年、每分鐘行情」仍待查證。

## Jev 的角色

預計使用 TypeSafe AI 的 Jev，接收整理好的市場狀態，嘗試回答明確問題，例如：

- 未來指定時間內，較可能上漲、盤整或下跌？
- 價格是否可能突破事先定義的區間？

Jev 官方提供選項、分數及機率等結構化輸出，但能否有效預測股價，需要實際驗證。把歷史資料送進 API 是提供當次判斷的參考，不等於已完成模型訓練。

若目標是畫出「未來每分鐘的預測價格線」，需要另外設計數值預測方法，並與 Jev 的方向判斷一起評估；不能直接把漲跌選項當成完整價格曲線。

## 預計使用流程

1. 選擇股票，確認免費 API 的資料範圍後，下載至少兩年的分鐘行情。
2. 儲存及清理資料，整理近期價格、成交量等分析資訊。
3. 設定預測目標，例如未來 30 分鐘，或未來幾天。
4. 將當時可取得的資訊交給 Jev，保存輸入、預測結果與時間。
5. 等實際行情發生後，比較結果，累積驗證紀錄。

資料以每分鐘收集，不代表一定要預測下一分鐘；預測多久之後的走勢需要獨立決定。

## 初版建議範圍

先選一檔股票與一個明確的預測時間範圍，完成「資料取得、Jev 判斷、歷史驗證、結果呈現」的完整流程。

歷史驗證時，依時間順序播放行情，只使用當時已知的資訊做預測，再揭開後續實際結果。保留一段未參與方法調整的資料作最後測試，並比較是否優於「價格維持不變」等簡單方法。

初版的成功標準是：能穩定取得資料、重現每次預測，並客觀量出效果。方向判斷與價格曲線應分別評估；兩年資料是否足夠，由測試結果決定。

## 尚待確認

- 市場、第一檔股票，以及符合歷史長度與分鐘細度要求的免費資料來源。
- 預測時間：未來幾分鐘、隔天，或未來幾天。
- 輸出重點：漲跌方向、價格區間，或逐分鐘價格曲線。
- 是否需要盤中更新，以及採用的程式語言與呈現方式。

## 白話例子

假設要預測未來 30 分鐘，就把歷史行情播放到某天上午 10:00，讓系統只看見 10:00 以前已完成的行情，預測到 10:30 的走勢；接著對照真實結果，檢查預測有多準。反覆在不同日期測試，才能知道這個方法是否有用。
